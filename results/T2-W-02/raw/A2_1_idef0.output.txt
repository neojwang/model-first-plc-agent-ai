### IDEF0 functional model

**Scope:** the controller for timed tank filling, rather than the physical movement of liquid. The context function is shown as **A0**, with its decomposition as **A1–A3**. In strict IDEF0 diagram numbering, the context diagram is **A-0**, containing function box **A0**.

External command and feedback signals are treated as **inputs**; the operating requirements and timing parameter are **controls**. Signal identifiers retain the required vocabulary.

| Node | Function | Inputs | Controls | Outputs | Mechanisms |
|---|---|---|---|---|---|
| **A0** | **Control timed tank filling** | `start`; `stop`; `LSHH` | `TimerDuration`; initial-step requirement; start-event requirement; elapsed-time and high-high termination requirements; stop-priority requirement; discharge-valve inhibition requirement | `fill_valve`; `discharge_valve` | OpenPLC Runtime; Factory I/O plant simulation; Modbus TCP interface |
| **A1** | **Determine the operating step** | `start`; `stop`; `LSHH`; `timer_done` | Initial step 0; step-transition rules; stop priority; filling-termination requirements | Operating-step status | OpenPLC sequence logic; operating-step memory |
| **A2** | **Measure the filling duration** | Operating-step status | `TimerDuration`; timer enablement during filling; timer reset in step 0 | `timer_done` | OpenPLC timer function; PLC time base |
| **A3** | **Set the valve commands** | Operating-step status | No-output requirement for step 0; fill-valve activation requirement for the filling step; permanent discharge-valve inhibition | `fill_valve`; `discharge_valve` | OpenPLC output logic; Modbus TCP output mapping |

### Meaning of the internal arrows and controls

- **Operating-step status** identifies either **step 0 (idle)** or **the filling step**. It connects **A1 → A2** and **A1 → A3**.
- **`timer_done`** is generated by **A2** and returned to **A1**. It is an internal arrow, not a physical PLC input.
- **A1 transition rules:**
  - Initially select step 0.
  - Give `stop` priority over every other transition: whenever it is TRUE, select step 0.
  - From step 0, accept `start` as a one-scan press event and select the filling step, provided `stop` and `LSHH` are FALSE.
  - From the filling step, select step 0 when `timer_done` or `LSHH` is TRUE.
- **A2 timer behavior:** start timing on entry to the filling step; assert `timer_done` when `TimerDuration` has elapsed; reset the timer in step 0.
- **A3 output behavior:** `fill_valve` is TRUE only in the filling step; `discharge_valve` is always FALSE. The sequence decision and output update must enforce the stop and termination requirements in the same control scan.

### I/O interpretation

- `start` is the rising-edge event derived from `StartCommand` at `%IX100.0`, not its continuously held level.
- `stop` corresponds to `StopCommand` at `%IX100.1`.
- `LSHH` corresponds to `%IX100.3`.
- `fill_valve` and `discharge_valve` correspond to `%QX100.0` and `%QX100.1`, respectively.
- **`LSH` at `%IX100.2` is available but unused by this task.** Detection at 2.4 m does not terminate filling under the stated requirements. Accordingly, it is not an active functional arrow in this model; adding an `LSH`-based transition would change the specification.
