Control task:
# Task T4 - Factory I/O Level Control, PID control

Plant: the tank of the Factory I/O "Level Control" scene in the analog configuration.

I/O (OpenPLC Runtime with Factory I/O attached as a Modbus TCP slave device; map the scene tags to these addresses in the Factory I/O driver):
- Inputs: StartCommand AT %IX100.0 : BOOL; StopCommand AT %IX100.1 : BOOL; LevelMeter AT %IW100 : INT (level meter, 0-10 V; the register value is proportional to the voltage).
- Outputs: FillValve AT %QW100 : INT (fill valve opening, 0-10 V); DischargeValve AT %QW101 : INT (discharge valve opening, 0-10 V).
- Constant: FULL_SCALE : INT := 1000 (the register value that corresponds to 10 V; the Factory I/O driver uses Scale = 100).
- Parameters: set point h_sp = h_target = 0.8 h_span; overfill limit h_max = 0.9 h_span; tolerance band eps = 0.02 h_span; hold time t_h = 10 s; PID gains Kp, Ti, Td; h_span is the measuring span of the level meter (10 V).

Requirements:
1. Step 0 is the initial step; it drives no output.
2. On StartCommand, regulate the level: drive the fill valve with the output of a PID controller (error e = h_sp - h), clamp the PID output to 0-100 % of the valve opening and suspend integration while the output is clamped, and hold the discharge valve at a constant opening of 40 % (4 V, that is, 0.4 FULL_SCALE).
3. End regulation when |e| <= eps has held for t_h, or when h >= h_max; then close both valves and return to step 0.
4. Whenever StopCommand is TRUE, return to step 0 with all outputs at 0.

Identifier vocabulary for receptivities and outputs (use exactly these names):
- inputs: start (the event of pressing StartCommand: TRUE only in the scan in which the button is pressed), stop, settled (|e| <= eps has held for t_h), r (level region: r = LOW for h < h_target, r = MID for h_target <= h < h_max, r = HIGH for h >= h_max)
- outputs: fill_valve (TRUE while the PID drives the fill valve), discharge_valve (TRUE while the discharge valve is held at 40 %)

## Functional controls and operating rules

### A1 — Signal interpretation

Use a common level basis throughout the model:

- h_sp = h_target = **0.8 h_span**
- h_max = **0.9 h_span**
- eps = **0.02 h_span**

On the register-equivalent basis, these correspond to a target of **800**, an overfill limit of **900**, and a tolerance of **20** counts.

### A2 — Level-condition evaluation

The region arrow **r** has exactly these values:

| Value | Condition |
|---|---|
| **LOW** | h < h_target |
| **MID** | h_target ≤ h < h_max |
| **HIGH** | h ≥ h_max |

The dwell timer runs only while regulation is active and |e| ≤ eps. It resets when regulation is inactive or |e| > eps. **settled** becomes TRUE after **10 s of uninterrupted in-band operation**; elapsed time is not accumulated across separate in-band intervals.

### A3 — Step supervision

| Priority | Condition | Result |
|---|---|---|
| Highest | **stop** = TRUE, from any step | Step 0; **fill_valve** = FALSE; **discharge_valve** = FALSE. |
| Next | Regulation active and either **settled** = TRUE or **r** = HIGH | Step 0; both permissions FALSE. |
| Next | Step 0 and **start** = TRUE, with **stop** = FALSE and **r** ≠ HIGH | Regulation step; both permissions TRUE. |
| Otherwise | No applicable transition | Existing step retained. |

Step 0 is the initial step and commands no valve opening. A start event at **r = HIGH** does not produce a one-scan valve-opening pulse. A held StartCommand does not restart regulation after completion; another rising edge is required.

### A4 — PID calculation

During regulation:

- Calculate the PID demand using **e = h_sp − h**.
- Clamp the demand to **0–100%**.
- Suspend integration whenever the output is clamped.
- Produce no active fill demand when **fill_valve** is FALSE or **stop** is TRUE.

PID initialization and inactive-state handling must be defined during detailed design; no particular reset or retained-integral policy is specified by the task.

### A5 — Output generation

- With **fill_valve** TRUE and **stop** FALSE: scale the bounded PID demand to **0–1000** for FillValve.
- With **discharge_valve** TRUE and **stop** FALSE: command **400** for DischargeValve.
- In step 0, or whenever **stop** is TRUE: command **0 to both registers**.

Stop and completion decisions must govern the output commands in the same PLC scan, rather than allowing stale PID or discharge commands to reach the output image.

Rules:
1. Step names start with the letter x followed by letters or digits (x0, x1, x21, xE1). The main graph is named G1, and x0 is its initial step.
2. A transition lists its upstream steps ("from"), its downstream steps ("to"), and its receptivity ("guard"). Guards use only the input identifiers of the task card, step names, the operators ! (not), & (and), | (or), parentheses, TRUE and FALSE; the level region of task T4 is tested as r = LOW, r = MID or r = HIGH.
3. "outputs" gives, for every output identifier of the task card, a Boolean expression over step names that is TRUE while the output is on.
4. "forcing" is optional: a separate graph (for example G0 for stop handling) may contain a step whose forcing order holds the graph named in "graph" in the listed situation.
5. "owned" lists every timer or hold condition used in a guard (timer_done, ton_q, tof_q, settled) with the step whose activity it measures, the value it has at the instant that step becomes active ("neutral"), and its preset, written as the parameter name of the task card ("preset"). Conditions that measure the duration of a step are FALSE at that instant; the off-delay output tof_q is measured by the pause step and is TRUE at that instant.
6. Output only the JSON object, without comments or explanations.
