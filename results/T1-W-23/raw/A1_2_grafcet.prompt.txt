Control task:
# Task T1 - Factory I/O Scene 2, From A to B (Set and Reset)

Plant: a conveyor transports a box from sensor A to sensor B (Factory I/O scene "From A to B (Set and Reset)").

I/O (OpenPLC Runtime with Factory I/O attached as a Modbus TCP slave device; map the scene tags to these addresses in the Factory I/O driver):
- Inputs: SensorA AT %IX100.0 : BOOL (TRUE while a box is detected at sensor A); SensorB AT %IX100.1 : BOOL (TRUE while a box is detected at sensor B).

Requirements:
1. When a box is detected at sensor A, start the conveyor.
2. When the box reaches sensor B, stop the conveyor so that the box stays at sensor B.
3. Use a bistable function block of IEC 61131-3 (SR or RS) for the conveyor command.

Identifier vocabulary for receptivities and outputs (use exactly these names):
- inputs: sensor_a, sensor_b
- output: conveyor

**Scope:** PLC control of the conveyor in Factory I/O Scene 2, “From A to B (Set and Reset).” The model transforms sensor indications into a retained conveyor command; it does not model the conveyor’s mechanical dynamics.

**Arbitration decision:** Use a **reset-dominant IEC 61131-3 RS bistable**. If both sensors are TRUE, stopping takes priority so that the conveyor does not move a box away from sensor B.

The context function is labeled **A0** as requested; in standard IDEF0 diagram numbering, its context diagram is **A-0**, and its decomposition diagram is **A0**.

Rules:
1. Step names start with the letter x followed by letters or digits (x0, x1, x21, xE1). The main graph is named G1, and x0 is its initial step.
2. A transition lists its upstream steps ("from"), its downstream steps ("to"), and its receptivity ("guard"). Guards use only the input identifiers of the task card, step names, the operators ! (not), & (and), | (or), parentheses, TRUE and FALSE; the level region of task T4 is tested as r = LOW, r = MID or r = HIGH.
3. "outputs" gives, for every output identifier of the task card, a Boolean expression over step names that is TRUE while the output is on.
4. "forcing" is optional: a separate graph (for example G0 for stop handling) may contain a step whose forcing order holds the graph named in "graph" in the listed situation.
5. "owned" lists every timer or hold condition used in a guard (timer_done, ton_q, tof_q, settled) with the step whose activity it measures, the value it has at the instant that step becomes active ("neutral"), and its preset, written as the parameter name of the task card ("preset"). Conditions that measure the duration of a step are FALSE at that instant; the off-delay output tof_q is measured by the pause step and is TRUE at that instant.
