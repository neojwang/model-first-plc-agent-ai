Control task:
# Task T4 - Factory I/O Level Control, PID control

Plant: the tank of the Factory I/O "Level Control" scene in the analog configuration.

I/O (OpenPLC Runtime with Factory I/O attached as a Modbus TCP slave device; map the scene tags to these addresses in the Factory I/O driver):
- Inputs: StartCommand AT %IX100.0 : BOOL; StopCommand AT %IX100.1 : BOOL; LevelMeter AT %IW100 : INT (level meter, 0-10 V; the register value is proportional to the voltage).
- Outputs: FillValve AT %QW100 : INT (fill valve opening, 0-10 V); DischargeValve AT %QW101 : INT (discharge valve opening, 0-10 V).
- Constant: FULL_SCALE : INT := 1000 (the register value that corresponds to 10 V; the Factory I/O driver uses Scale = 100).
- Parameters: set point h_sp = h_target = 0.8 h_span; overfill limit h_max = 0.9 h_span; tolerance band eps = 0.02 h_span; hold time t_h = 10 s; PID gains Kp, Ti, Td; h_span is the measuring span of the level meter (10 V).

Requirements:
1. Step 0 is the initial step; it drives no output.
2. On StartCommand, regulate the level: drive the fill valve with the output of a PID controller (error e = h_sp - h), clamp the PID output to 0-100 % of the valve opening and suspend integration while the output is clamped, and hold the discharge valve at a constant opening of 40 % (4 V, that is, 0.4 FULL_SCALE).
3. End regulation when |e| <= eps has held for t_h, or when h >= h_max; then close both valves and return to step 0.
4. Whenever StopCommand is TRUE, return to step 0 with all outputs at 0.

Identifier vocabulary for receptivities and outputs (use exactly these names):
- inputs: start (the event of pressing StartCommand: TRUE only in the scan in which the button is pressed), stop, settled (|e| <= eps has held for t_h), r (level region: r = LOW for h < h_target, r = MID for h_target <= h < h_max, r = HIGH for h >= h_max)
- outputs: fill_valve (TRUE while the PID drives the fill valve), discharge_valve (TRUE while the discharge valve is held at 40 %)

## Arrow definitions and constraints

### External I/O and calibration

| Arrow or control | Definition |
|---|---|
| StartCommand signal | `StartCommand AT %IX100.0 : BOOL` |
| StopCommand signal | `StopCommand AT %IX100.1 : BOOL` |
| LevelMeter register value | `LevelMeter AT %IW100 : INT` |
| FillValve register command | `FillValve AT %QW100 : INT`, constrained to 0–1000 |
| DischargeValve register command | `DischargeValve AT %QW101 : INT`, either 0 or 400 |
| FULL_SCALE calibration | `FULL_SCALE = 1000` represents 10 V; Factory I/O driver Scale = 100 |
| Measured level | \(h=(\text{LevelMeter}/1000)\,h_{\text{span}}\) |
| Level set point / level target | \(h_{sp}=h_{\text{target}}=0.8h_{\text{span}}\), equivalent to register value 800 |
| Overfill limit | \(h_{\max}=0.9h_{\text{span}}\), equivalent to register value 900 |
| Tolerance band | \(\varepsilon=0.02h_{\text{span}}\), equivalent to 20 register counts |
| Hold duration | \(t_h=10\,\text{s}\) |

### Required identifier vocabulary

| Arrow | Meaning |
|---|---|
| `start` | Rising-edge event of StartCommand; TRUE only during the scan in which the button is pressed |
| `stop` | Current Boolean state of StopCommand |
| `settled` | TRUE when \(\lvert h_{sp}-h\rvert\leq\varepsilon\) has remained continuously true for 10 s during regulation |
| `r` | LOW when \(h<h_{\text{target}}\); MID when \(h_{\text{target}}\leq h<h_{\max}\); HIGH when \(h\geq h_{\max}\) |
| `fill_valve` | TRUE while PID demand controls the fill valve |
| `discharge_valve` | TRUE while the discharge valve is commanded to 40% opening |

`fill_valve` and `discharge_valve` are **Boolean operating permissions**, not analog valve magnitudes.

## Child-function coordination

The principal internal arrows are:

- **A1 → A2:** `start`, `stop`, `r`.
- **A1 → A3:** measured level.
- **A2 → A3:** `fill_valve`.
- **A2 → A4:** `fill_valve`.
- **A2 → A5:** `fill_valve`, `discharge_valve`.
- **A3 → A4:** level error.
- **A3 → A5:** bounded fill demand.
- **A4 → A2:** `settled`.
- **A5 → A0 boundary:** FillValve register command; DischargeValve register command.

The following constraints define the controls applied to those functions:

### A2 — Operating-sequence rules

| Condition | Resulting state and permissions |
|---|---|
| Initialization | Step 0; `fill_valve = FALSE`; `discharge_valve = FALSE` |
| `stop = TRUE`, in any state | Step 0; both permissions FALSE |
| Step 0, `start = TRUE`, `stop = FALSE`, and `r` other than HIGH | Regulation step; both permissions TRUE |
| Regulation step, `settled = TRUE` or `r = HIGH` | Step 0; both permissions FALSE |
| No applicable transition | Existing state retained |

Stop and overfill termination take precedence over starting or continuing regulation. A held StartCommand does not cause an automatic restart: a new `start` event is required.

### A3 — PID constraints

- Level error: \(e=h_{sp}-h\).
- PID action: positive error produces increased fill demand.
- Bounded fill demand: 0–100% opening.
- Integration is suspended while the PID output is clamped.
- PID integration is inactive when `fill_valve = FALSE`.
- PID gains are \(K_p,T_i,T_d\); their numerical tuning and the PID update interval remain implementation parameters.

### A4 — Settling constraints

The settling timer runs only while `fill_valve = TRUE` and \(\lvert e\rvert\leq\varepsilon\). It resets when either condition becomes false. Thus, separate visits to the tolerance band do not accumulate toward the 10 s requirement.

### A5 — Output constraints

- With `fill_valve = TRUE`, the bounded PID demand is scaled to the FillValve register range 0–1000.
- With `discharge_valve = TRUE`, the DischargeValve register command is \(0.4\times1000=400\), corresponding to 4 V.
- A FALSE permission forces its corresponding register command to zero.
- Step 0 therefore has **no active valve output**: both registers are explicitly zero, rather than retaining previous values.

{
  "graphs": [ {"name": "G1", "steps": ["x0", "x1"], "initial": ["x0"]} ],
  "transitions": [ {"id": "t1", "from": ["x0"], "to": ["x1"], "guard": "start"} ],
  "outputs": { "fill_valve": "x1" },
  "forcing": [ {"by": "x11", "graph": "G1", "situation": ["x0"]} ],
  "owned": { "timer_done": {"step": "x1", "neutral": false, "preset": "TimerDuration"} }
}

Rules:
1. Step names start with the letter x followed by letters or digits (x0, x1, x21, xE1). The main graph is named G1, and x0 is its initial step.
2. A transition lists its upstream steps ("from"), its downstream steps ("to"), and its receptivity ("guard"). Guards use only the input identifiers of the task card, step names, the operators ! (not), & (and), | (or), parentheses, TRUE and FALSE; the level region of task T4 is tested as r = LOW, r = MID or r = HIGH.
3. "outputs" gives, for every output identifier of the task card, a Boolean expression over step names that is TRUE while the output is on.
4. "forcing" is optional: a separate graph (for example G0 for stop handling) may contain a step whose forcing order holds the graph named in "graph" in the listed situation.
5. "owned" lists every timer or hold condition used in a guard (timer_done, ton_q, tof_q, settled) with the step whose activity it measures, the value it has at the instant that step becomes active ("neutral"), and its preset, written as the parameter name of the task card ("preset"). Conditions that measure the duration of a step are FALSE at that instant; the off-delay output tof_q is measured by the pause step and is TRUE at that instant.
6. Output only the JSON object, without comments or explanations.
