## 1. Model conventions

The model uses **A0** for the context function and **A1–A5** for its decomposition. All function names are verb phrases. Arrow names are noun phrases or the specified signal identifiers.

- **Inputs** are transformed by a function.
- **Controls** govern its execution.
- **Outputs** are its results.
- **Mechanisms** provide the resources used to execute it.
- “Step 0 drives no output” is interpreted as **both analog output commands equal zero**, not as leaving their previous values unchanged.
- `fill_valve` and `discharge_valve` are Boolean action-enable signals, not the analog output values.

### Signal and scaling definitions

| Arrow name | Meaning |
|---|---|
| `start` | Rising-edge event of `StartCommand`; TRUE for one PLC scan only |
| `stop` | Current Boolean value of `StopCommand` |
| Level measurement `h` | Engineering-unit level derived from `LevelMeter` |
| Level error `e` | `h_sp − h` |
| `settled` | TRUE after `\|e\| ≤ eps` has remained continuously true for `t_h` during regulation |
| `r` | `LOW` when `h < h_target`; `MID` when `h_target ≤ h < h_max`; `HIGH` when `h ≥ h_max` |
| `fill_valve` | TRUE while PID control of the fill valve is enabled |
| `discharge_valve` | TRUE while the discharge valve's fixed 40% command is enabled |

The scaling relationships are:

\[
h=\frac{\text{LevelMeter}}{\text{FULL\_SCALE}}h_{\text{span}},
\qquad
h_{sp}=h_{target}=0.8h_{\text{span}},
\qquad
h_{max}=0.9h_{\text{span}},
\qquad
eps=0.02h_{\text{span}}.
\]

With `FULL_SCALE = 1000`, the equivalent register-domain values are **800** for the target, **900** for the overfill limit, **20** for the tolerance, and **400** for the discharge command.

Here, **regulation status** identifies whether step 0 or the regulation step is active. It feeds back from A3 to A2 so that the settling timer cannot accumulate time while the sequence is idle.

## 5. Functional rules

### A2 — Evaluate level conditions

- Determine `r` using the specified level boundaries.
- Accumulate settling time only while regulation is active and `|e| ≤ eps`.
- Reset the settling timer whenever regulation is inactive or `|e| > eps`.
- Assert `settled` when the uninterrupted qualifying interval reaches `t_h`.

Thus, previous time in tolerance cannot carry over into a new regulation cycle.

### A3 — Supervise the regulation sequence

The additional regulation step is designated **step 1**.

| Current step | Receptivity | Next step | Resulting action enables |
|---|---|---|---|
| Any step | `stop` | Step 0 | `fill_valve = FALSE`; `discharge_valve = FALSE` |
| Step 0 | `NOT stop AND start AND r ≠ HIGH` | Step 1 | `fill_valve = TRUE`; `discharge_valve = TRUE` |
| Step 0 | Otherwise | Step 0 | Both FALSE |
| Step 1 | `NOT stop AND (settled OR r = HIGH)` | Step 0 | Both FALSE |
| Step 1 | `NOT stop AND NOT settled AND r ≠ HIGH` | Step 1 | Both TRUE |

**Priority and boundary behavior:**

- `stop` has unconditional priority over `start` and all other conditions.
- A start at `r = HIGH` produces no valve actuation: the overfill termination condition is already satisfied.
- `r = MID` alone does not end regulation; termination requires `settled` or `r = HIGH`.
- Holding `StartCommand` TRUE does not restart a completed cycle. A new `start` event requires another button press.
- Step 0 is the initialized state.

### A4 — Calculate the bounded PID demand

During enabled regulation:

\[
u_{\text{raw}}=\operatorname{PID}(e;K_p,T_i,T_d),
\qquad
u=\operatorname{clamp}(u_{\text{raw}},0,100\%).
\]

- The bounded fill demand is `u`.
- Integration is suspended while the PID output is clamped; the integral state is held during that interval.
- No enabled PID valve action exists when `fill_valve = FALSE` or `stop = TRUE`.
- PID reset, derivative initialization, and idle-state retention are implementation choices not otherwise specified by the task; they must not defeat the zero-output or integration-suspension requirements.

### A5 — Apply the valve commands

| Condition | `FillValve` command | `DischargeValve` command |
|---|---:|---:|
| `stop = TRUE` | `0` | `0` |
| `stop = FALSE` and both action enables are TRUE | Integer-scaled bounded fill demand: `u / 100% × FULL_SCALE` | `0.4 × FULL_SCALE = 400` |
| Step 0 / both action enables FALSE | `0` | `0` |

The bounded fill command is therefore **0–1000**. Transition and stop decisions govern the commands written in the same scan, so returning to step 0 closes both valves without retaining the previous analog values.
