# Task T4 - Factory I/O Level Control, PID control

Plant: the tank of the Factory I/O "Level Control" scene in the analog configuration.

I/O (OpenPLC Runtime with Factory I/O attached as a Modbus TCP slave device; map the scene tags to these addresses in the Factory I/O driver):
- Inputs: StartCommand AT %IX100.0 : BOOL; StopCommand AT %IX100.1 : BOOL; LevelMeter AT %IW100 : INT (level meter, 0-10 V; the register value is proportional to the voltage).
- Outputs: FillValve AT %QW100 : INT (fill valve opening, 0-10 V); DischargeValve AT %QW101 : INT (discharge valve opening, 0-10 V).
- Constant: FULL_SCALE : INT := 1000 (the register value that corresponds to 10 V; the Factory I/O driver uses Scale = 100).
- Parameters: set point h_sp = h_target = 0.8 h_span; overfill limit h_max = 0.9 h_span; tolerance band eps = 0.02 h_span; hold time t_h = 10 s; PID gains Kp, Ti, Td; h_span is the measuring span of the level meter (10 V).

Requirements:
1. Step 0 is the initial step; it drives no output.
2. 3. End regulation when |e| <= eps has held for t_h, or when h >= h_max; then close both valves and return to step 0.
4. Whenever StopCommand is TRUE, return to step 0 with all outputs at 0.

Identifier vocabulary for receptivities and outputs (use exactly these names):
- inputs: start (the event of pressing StartCommand: TRUE only in the scan in which the button is pressed), stop, settled (|e| <= eps has held for t_h), r (level region: r = LOW for h < h_target, r = MID for h_target <= h < h_max, r = HIGH for h >= h_max)
- outputs: fill_valve (TRUE while the PID drives the fill valve), discharge_valve (TRUE while the discharge valve is held at 40 %)

### Functional definitions and interconnections

- **A1 — signal interpretation**
  - `start` is TRUE only for the scan detecting a press of StartCommand, not continuously while the button is held.
  - `stop` follows StopCommand.
  - \(h=(\text{LevelMeter}/1000)\,h_{\text{span}}\).

- **A2 — condition evaluation**
  - \(e=h_{sp}-h\).
  - `r` = LOW when \(h<h_{\text{target}}\), MID when \(h_{\text{target}}\le h<h_{\max}\), and HIGH when \(h\ge h_{\max}\).
  - `settled` becomes TRUE after \(|e|\le eps\) has remained continuously true for 10 s **during regulation**. The timer resets when the band condition fails or regulation is inactive.

- **A3 — state management**
  - Initially, step 0 sets both enables FALSE.
  - `stop` has highest priority: return to step 0 and set both enables FALSE.
  - In step 0, `start` initiates regulation, subject to the stop and high-level protections.
  - During regulation, both enables are TRUE until `settled` is TRUE or `r` is HIGH; then both become FALSE and the controller returns to step 0.
  - A continuously held StartCommand does not restart regulation; a new press is required.

- **A4 — PID demand**
  - Compute the PID demand from e, clamp it to 0–100%, and suspend integral accumulation while clamped.
  - Inactive regulation cannot produce an effective valve command; no particular inactive PID-state reset strategy is specified by the task.

- **A5 — output conversion**
  - If `fill_valve` is TRUE, the FillValve command is the bounded PID percentage scaled to 0–1000; otherwise it is 0.
  - If `discharge_valve` is TRUE, the DischargeValve command is 400; otherwise it is 0.
  - Thus step 0, completion, overfill protection, and `stop` all produce zero commands to both valves.
