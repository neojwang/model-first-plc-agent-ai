Control task:
# Task T2 - Factory I/O Scene 3, Filling Tank (Timers), simple timer

Plant: a tank in the digital configuration, saved as a user scene and customized with two capacitive level switches.

I/O (OpenPLC Runtime with Factory I/O attached as a Modbus TCP slave device; map the scene tags to these addresses in the Factory I/O driver):
- Inputs: StartCommand AT %IX100.0 : BOOL; StopCommand AT %IX100.1 : BOOL; LSH AT %IX100.2 : BOOL (level switch high at the target level, 2.4 m; TRUE when liquid is detected); LSHH AT %IX100.3 : BOOL (level switch high-high at the overfill limit, 2.7 m; TRUE when liquid is detected).
- Outputs: FillValve AT %QX100.0 : BOOL (TRUE opens the fill valve); DischargeValve AT %QX100.1 : BOOL (keep FALSE in this task).
- Parameter: TimerDuration : TIME.

Requirements:
1. Step 0 is the initial step; it drives no output.
2. On StartCommand, open the fill valve and start a timer of duration TimerDuration.
3. Close the fill valve when the timer has elapsed or when LSHH detects the liquid, whichever comes first, and then return to step 0.
4. Whenever StopCommand is TRUE, return to step 0 with all outputs FALSE.

Identifier vocabulary for receptivities and outputs (use exactly these names):
- inputs: start (the event of pressing StartCommand: TRUE only in the scan in which the button is pressed), stop, LSH, LSHH, timer_done (the timer of the filling step has elapsed)
- outputs: fill_valve, discharge_valve

## Control definitions

- **Initial-step requirement:** initialize the sequence in step 0, with both outputs FALSE.
- **Step-transition rules:**
  - In step 0, `start` permits entry into step 1 only when `stop` and `LSHH` are FALSE.
  - In step 1, `timer_done` or `LSHH` causes return to step 0.
  - A `start` event during step 1 does not restart or extend filling.
- **Stop-priority rule:** whenever `stop` is TRUE, select step 0 and force both outputs FALSE, regardless of other conditions.
- **Timer-start rule:** start a new interval upon entry into step 1.
- **Timer-reset rule:** clear elapsed time and `timer_done` outside step 1; a subsequent filling cycle receives a fresh interval.
- **Step-output rules:** `fill_valve` is TRUE only while step 1 is selected and none of `stop`, `LSHH`, or `timer_done` is TRUE. Otherwise it is FALSE.
- **Discharge-inhibition rule:** `discharge_valve` remains FALSE in every state.

The A2–A3 feedback represents state and timer interaction, **not a mandated extra scan of delay**. Timer expiry, overfill detection, and stop must suppress the fill command in the scan in which they are recognized.

GRAFCET JSON schema (the tuple of Equation (1) of the paper):

{
  "graphs": [ {"name": "G1", "steps": ["x0", "x1"], "initial": ["x0"]} ],
  "transitions": [ {"id": "t1", "from": ["x0"], "to": ["x1"], "guard": "start"} ],
  "outputs": { "fill_valve": "x1" },
  "forcing": [ {"by": "x11", "graph": "G1", "situation": ["x0"]} ],
  "owned": { "timer_done": {"step": "x1", "neutral": false, "preset": "TimerDuration"} }
}

Rules:
1. Step names start with the letter x followed by letters or digits (x0, x1, x21, xE1). The main graph is named G1, and x0 is its initial step.
2. A transition lists its upstream steps ("from"), its downstream steps ("to"), and its receptivity ("guard"). Guards use only the input identifiers of the task card, step names, the operators ! (not), & (and), | (or), parentheses, TRUE and FALSE; the level region of task T4 is tested as r = LOW, r = MID or r = HIGH.
3. "outputs" gives, for every output identifier of the task card, a Boolean expression over step names that is TRUE while the output is on.
4. "forcing" is optional: a separate graph (for example G0 for stop handling) may contain a step whose forcing order holds the graph named in "graph" in the listed situation.
5. "owned" lists every timer or hold condition used in a guard (timer_done, ton_q, tof_q, settled) with the step whose activity it measures, the value it has at the instant that step becomes active ("neutral"), and its preset, written as the parameter name of the task card ("preset"). Conditions that measure the duration of a step are FALSE at that instant; the off-delay output tof_q is measured by the pause step and is TRUE at that instant.
6. Output only the JSON object, without comments or explanations.
