# Agent AI for PLC programming: prompts, scoring scripts, and model-checking files

This repository accompanies the paper "Teaching Programmable Logic Controller Programming and Verification with Agent AI: A Model-First IDEF0–GRAFCET Workflow in a Virtual Factory". It contains everything needed to repeat the code-generation experiment (RQ1) and the cross-check of the verification lane (RQ2); it contains no student data.

Status: the materials are released before the experiment. The prompts are frozen with `exec/freeze_prompts.py` after two pilots of eight rows each (one row per task and condition, not counted) and before the first generation of the run plan, and the results (`results/`) are added after the experiment. License: MIT (see `LICENSE`).

| Path | Content |
|---|---|
| `exec/prompts/tasks/` | Task cards T1–T4 (Factory I/O Scene 2, customized Scene 3 with two timer strategies, Level Control with PID) |
| `exec/prompts/templates/` | Prompt templates: A1 lane (IDEF0, GRAFCET as JSON, ST code), A2 lane (independently phrased), single-lane baseline (ST code directly); `_schema.md` is the GRAFCET JSON schema |
| `exec/render_prompt.py` | Fills a template with a task card and the earlier response of the same lane |
| `exec/run_llm.py` | Generates the responses of the run plan through the OpenAI Responses API with the registered settings (model gpt-6.1-sol, reasoning effort medium, no temperature or top_p, no system message, no tools, a new conversation per lane) and either of two access routes: an OpenAI API key (at most 64,000 output tokens per response) or a ChatGPT plan through Sign in with ChatGPT (streamed responses; this route accepts no output cap); transcribes the GRAFCET JSON and the ST code from the fenced code blocks of each response, keeps the full responses, and logs every call with its access route, settings hash, and token usage; `--selftest` runs against local mock servers |
| `exec/freeze_prompts.py` | SHA-256 manifest of the prompts and of `run_llm.py` (`exec/prompts_manifest.json`, added once the prompts are frozen), written after the pilot and before the first generation of the run plan, and verified before every session |
| `exec/make_release.py` | Builds this repository from the experiment kit: copies the public files and, after the experiment, the run sheet and the text artifacts with the SHA-256 of each (`results/manifest.csv`) |
| `exec/make_run_plan.py`, `exec/run_plan.csv` | Randomized run plan: 4 tasks × 2 conditions × 30 samples (seed 20261112) |
| `docs/use_case_variables.md` | Variables of the three tank use cases referred to in Section 5.2 of the paper, with the names and addresses of the task cards |
| `exec/scene_tests_en.md` | Scene tests and pass criteria |
| `exec/compile_check.py` | Compile check (compiled, a2_compiled): repeats the first three steps of the compilation script of OpenPLC Runtime version 3 at the pinned commit (iec2c, then g++ on Config0.c and Res0.c), writes the compilation log, and writes the file to upload for the scene test |
| `exec/scene_sim.py` | Scene tests (scene_test_pass, a2_scene_test_pass) by closed-loop simulation: the compiled program, run as OpenPLC Runtime runs it (one scan per task interval of its configuration), drives models of the Factory I/O scenes (nominal scene model v1, documented in `scene_tests_en.md`); no Factory I/O needed; `--sensitivity` reruns under alternative assumptions |
| `exec/set_params.py` | Sets the scene-test parameters of an upload file for one situation (timer durations of T2 and T3, PID gains of T4) and prints the log stored in test_log |
| `exec/compare_grafcet.py` | Criterion (iii): consistency of the A1 and A2 GRAFCET models (one-to-one correspondence of steps and transitions, receptivities and outputs compared over all input combinations, timers compared by owning step and preset) |
| `exec/score_models.py` | Fills the model columns of the run sheet: criterion (iii) and, for the tank tasks, the model check of the A1 GRAFCET (writes a NuSMV model per sample) |
| `nusmv/grafcet2smv.py` | GRAFCET (JSON) to NuSMV translator with an explicit-state pre-check; one model step is one evolution to a stable situation |
| `nusmv/run_nusmv.py` | Runs NuSMV 2.6 on the reference model and its seeded faults (`--reference`; result in `nusmv/formal_log.txt`) and on the model of every tank-task sample; maps each verdict to P1–P4 by formula text and enters it in the run sheet, listing every run in `nusmv_runs.csv` |
| `nusmv/tank_reference.*` | Reference GRAFCET of the tank tasks, its NuSMV model, and the pre-check log (properties P1–P4, well-formedness W1–W5, seeded faults) |
| `gvm/` | GRAFCET as the description language of a GRAFCET virtual machine: `grafcet2gvm.py` generates equivalent Python, C++, and ST programs from a GRAFCET description (one evolution to a stable situation per tick, with the semantics of the NuSMV model); `e3_check.py` runs them in lockstep with the model and counts the ticks with any difference (E3); `generated/` holds the programs of the reference GRAFCET of the tank tasks, `e3_log.txt` the result, and `gvm_colab.ipynb` a Google Colab notebook for the Python and C++ programs |
| `gvm/st_match.py`, `gvm/st_match_log.txt` | Synchronous check of an ST program against the GVM program of its GRAFCET: in every registered situation the GVM program drives the scene model and the ST program, compiled with matiec, gets the same inputs in every scan; the valve and conveyor outputs are compared (in T4 the discharge valve and a closed fill valve outside regulation, not the PID opening); a difference lasting one scan is tolerated. Fills `st_gvm_match` and `st_gvm_lasting` (and the `a2_` columns) and writes `st_gvm_runs.csv`. `--reference` checks the reference ST programs against the reference GRAFCETs and seeded faults on both sides (result in `gvm/st_match_log.txt`) |
| `gvm/gvm_scene.py`, `gvm/reference/`, `gvm/scene_log.txt` | The GRAFCET model of every workflow sample (A1 and A2 lanes) runs as the Python and the C++ program of the GVM in the registered situations of the scene tests; the I/O of the task card is bound the same way for every GRAFCET (start event, level region, owned timers with the presets of the situation, the PID of the T4 reference program); fills `gvm_py_scene_pass`, `gvm_cpp_scene_pass` and `gvm_e3` (and the `a2_` columns) and writes `gvm_runs.csv`. `--reference` checks the four reference GRAFCETs and eleven seeded faults (result in `gvm/scene_log.txt`) |
| `pilot/reference/`, `pilot/upload/` | Hand-written reference programs for T1–T4 (one PROGRAM Main that calls one FUNCTION_BLOCK, as the prompts require) and the same programs with the fixed 20 ms configuration added by `exec/compile_check.py`; they check the scoring tools and are not samples of the experiment |
| `pilot/vc/vc_check.py`, `pilot/vc/vc_log.txt` | Check of the scene simulator against programs with known verdicts, used in place of a comparison with runs in Factory I/O: the references pass every registered scene test with the fixed 20 ms configuration and with their own configurations at 10 ms and 100 ms, and in 750 test runs over 288 combinations of the alternative assumptions; each of 11 seeded faults, and each reference under two configuration faults (normally closed stop button, driver Scale 1), fails at least one scene test; properties P1–P4 are also checked scan by scan on the compiled code |
| `analysis/analysis.py` | Wilson intervals, pass@k, Fisher's exact test, Cochran–Mantel–Haenszel test (primary test of RQ1), false accepts and Cohen's kappa (RQ2), and the GRAFCET models run as GVM programs (the primary measure of RQ1 since 2026-11-14, decided after the first pilot) with the check of the ST programs against them; `--table9` writes the results table of Section 5.5 |
| `analysis/power_sim.py` | Monte Carlo power of the Cochran–Mantel–Haenszel test quoted in Section 3.2 |
| `results/` (added after the experiment) | Run sheet `runs.csv`; the text artifacts of every sample (IDEF0 and GRAFCET models, ST code, NuSMV models, compilation and test logs); the raw responses of the model (`<run_id>/raw/`) and the call log with the token usage of every call (`llm_ledger.jsonl`); `manifest.csv` with the SHA-256 of every artifact. Screen recordings of the scene tests are listed in the manifest but not included |

Usage:

```
python3 exec/freeze_prompts.py                          # once, before the first generation
python3 exec/render_prompt.py T2 A1_1_idef0             # prompt for one stage
python3 exec/compile_check.py --openplc OPENPLC_V3_DIR runs.csv --base ARTIFACTS --write
python3 exec/set_params.py ARTIFACTS/<run_id>/a1_code_openplc.st T2 a   # file to upload for situation (a)
python3 exec/scene_sim.py --openplc OPENPLC_V3_DIR runs.csv --base ARTIFACTS --write --sensitivity
python3 exec/score_models.py runs.csv --base ARTIFACTS --write
python3 nusmv/run_nusmv.py --nusmv NUSMV_BINARY runs.csv --base ARTIFACTS --write
python3 gvm/gvm_scene.py runs.csv --base ARTIFACTS --write         # GRAFCET models as GVM programs
python3 gvm/st_match.py --openplc OPENPLC_V3_DIR runs.csv --base ARTIFACTS --write   # ST programs against them
python3 analysis/analysis.py runs.csv --table9 table9.csv > report.md
python3 gvm/e3_check.py nusmv/tank_reference.json --openplc OPENPLC_V3_DIR --out gvm/generated   # GVM programs
cd pilot/vc && python3 vc_check.py --openplc OPENPLC_V3_DIR --pilot ..   # check of the scene simulator
```

Python 3 is required (`run_llm.py` uses the standard library only and needs an OpenAI API key or a ChatGPT Plus or Pro plan); numpy and scipy are used by `power_sim.py` and, when installed, by `analysis.py`; NuSMV 2.6 is required for the formal model check; g++ with C++17 runs the C++ programs of `gvm/`; the compile check and the scene simulation need OpenPLC_v3 at commit b5d41356dab4aeadca0dd7ca64ba542f870b595d with matiec built (flex, bison, libtool and g++); Factory I/O is not needed: the scene tests run in the simulator, and the simulated verdicts were not compared with runs in Factory I/O. Self-tests: `python3 exec/compare_grafcet.py --selftest`, `python3 exec/set_params.py --selftest`, `python3 exec/scene_sim.py --openplc OPENPLC_V3_DIR --selftest`, `python3 analysis/analysis.py --selftest`, `python3 nusmv/grafcet2smv.py nusmv/tank_reference.json --check --mutants`, `python3 nusmv/run_nusmv.py --selftest [--nusmv NUSMV_BINARY]`, `python3 gvm/gvm_scene.py --selftest`, `python3 gvm/st_match.py --openplc OPENPLC_V3_DIR --selftest`, `python3 gvm/e3_check.py nusmv/tank_reference.json` (Python and C++ only; add `--openplc` for the ST program).

## Changes after the pilots

- After the first pilot: the three ST templates ask for code that compiles with matiec (located variables in a VAR block of their own; no keywords or names of standard functions as identifiers or enumeration values; at least one statement in every CASE branch).
- After the second pilot: the return to step 0 in the scene tests is checked in the same way for ST programs and for the GVM programs of GRAFCET models; when the tank already meets the end condition of the started step, a new start may open the fill valve for at most one scan, and the tank is then emptied before the check (`exec/scene_sim.py`, `exec/scene_tests_en.md`).
- After the second pilot: in the comparison of an ST program with the GVM program of its GRAFCET (`gvm/st_match.py`), a level count that lies exactly on the edge of the tolerance band of the PID task may be read inside or outside the band.
- After the second pilot: `exec/run_llm.py` sends the host identifier of Sign in with ChatGPT as `urn:uuid:…`, the format given in the OpenAI documentation for UUID-based host IDs; this concerns the sign-in only, not the requests to the model. The prompts were frozen after these changes (`exec/prompts_manifest.json`).
